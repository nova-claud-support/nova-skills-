# Spec First Development

## Purpose
Translate product requests into testable specifications before implementation.

## Workflow
1. Clarify users, goals, non-goals, and constraints.
2. Write observable acceptance criteria and edge cases.
3. Define API contracts, data shapes, and state transitions.
4. Identify privacy, accessibility, performance, and security requirements.
5. Map requirements to tests.
6. Record assumptions and version scope changes.

## Deliverables
- Functional specification
- acceptance criteria
- API/data contract
- traceability matrix.

## Verification
- Confirm scope, constraints, and acceptance criteria.
- Ground decisions in repository evidence.
- Run relevant checks and report exact outcomes.
- Record unresolved assumptions and risks.

## Safety
Do not infer consent for sensitive data collection or consequential actions from vague requirements.

## Completion report
State scope, files inspected or changed, evidence, checks run, outcomes, remaining risks, and approvals required. Never fabricate tool output or test results. Preserve user work and prefer minimal, reversible changes.
