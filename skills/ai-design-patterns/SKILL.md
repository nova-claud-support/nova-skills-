# Ai Design Patterns

## Purpose
Apply software design patterns to AI-enabled systems with explicit uncertainty and tool boundaries.

## Workflow
1. Use Strategy for provider choice, Adapter for provider normalization, Pipeline for staged processing, State Machine for auditable workflows, Circuit Breaker for outages, Cache with invalidation, and Human-in-the-Loop for consequential actions.
2. Document complexity, trade-offs, and failure modes.

## Deliverables
- Architecture decision record
- component diagram
- failure-mode tests.

## Verification
- Confirm scope, constraints, and acceptance criteria.
- Ground decisions in repository evidence.
- Run relevant checks and report exact outcomes.
- Record unresolved assumptions and risks.

## Safety
Validate model output independently. Generated text is not verified fact or authorization.

## Completion report
State scope, files inspected or changed, evidence, checks run, outcomes, remaining risks, and approvals required. Never fabricate tool output or test results. Preserve user work and prefer minimal, reversible changes.
